# Pine of Glass 0.18.3

All four extensions now respect `PI_CODING_AGENT_DIR` when reading global configuration.

Previously, Pine always read from `~/.pi/agent`, even when Pi used a different agent
directory. Pine now uses Pi's public `getAgentDir()` API, including its `~/` expansion.
The default location is unchanged. Project configuration still overrides global
configuration, and `PI_CONTEXTIMATE_CONFIG` files still apply last.

Thanks to [@hifanx](https://github.com/hifanx) for reporting
[issue #185](https://github.com/tmustier/pine-of-glass/issues/185).
Fixed in [PR #187](https://github.com/tmustier/pine-of-glass/pull/187).

## Verification

Lint, typecheck and all 538 tests pass. The config regressions fail against the old
lookup. A live Pi 1.4.0 session loaded the custom config despite conflicting settings
in the default directory, then GPT-6.1 Sol executed actual write/read tools with no
extension errors. The minimum supported Pi version was not separately exercised.
